Two deployable binaries

cmd/server — the GraphQL API with HTTP server, JWT middleware, rate limiting, and graceful shutdown
cmd/worker — the Temporal worker that executes order lifecycle activities

GraphQL layer (graph/schema.graphql + internal/graph/)

Full schema: Users, Products (Flower/Oil/Edible/Extraction), Orders with pagination
Resolvers for auth, products (CRUD + filtered search), and orders
RBAC enforced at resolver level (CUSTOMER / SELLER / ADMIN)

Temporal order workflow — the full sale lifecycle:
PENDING → PAYMENT_PROCESSING → PAYMENT_CONFIRMED → PREPARING → SHIPPED → DELIVERED
Stock is reserved atomically via MongoDB transactions, and released automatically on cancellation or payment timeout (30 min). The workflow is signal-driven and fully durable.
Security hardening throughout:

bcrypt passwords with timing-safe login (prevents user enumeration)
Separate JWT secrets for access (15 min) and refresh (7 days) tokens
Client prices are ignored — order totals are always resolved from DB
Per-IP rate limiter, security headers, introspection disabled in production
MongoDB schema-level validators + least-privilege app user
FROM scratch Docker images — no shell, no OS attack surface

To get running:
cp .env.example .env
make gen-secrets   # fill in the output values into .env
make dev           # starts MongoDB + Temporal + API + Worker
make generate      # run gqlgen to produce the GraphQL boilerplate
Then open http://localhost:8080/playground
